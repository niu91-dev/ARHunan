一、项目定位：它是什么，不是什么

它是什么

  • 一个纯前端 Three.js（r180）WebGL 三维地形沙盘演示，模拟"站在实体沙盘边缘、通过支架上 Pad 观察"的视角。
  • 用真实高程数据（湖南省 DEM）生成地形，叠加"全息扫描"风格的点云与连线动效。
  • 11 个真实经纬度地点锚点 + 资料卡展开交互，参考 HoloLens 空间界面语言。
  • 含摄像头画面合成预览，用于评估"实景叠加"观感。

它不是什么

  • 不是真实 AR/MR 应用：没有空间定位、SLAM、环境遮挡或设备位姿跟踪。摄像头仅为屏幕视觉合成。
  • 不是测绘/工程工具：高程做了垂直夸张，地点为代表性示意锚点，非 GIS 边界。
  • 不是 HoloLens 原生应用：仅借鉴其设计原则，非官方组件、未认证。
  • 不是成品展项：README 明确标注"用于视觉与交互效果验证"。

渲染核心：一次生成，四个着色器共享 uniform

地形、点云、连线、地面光标分别使用 MeshStandardMaterial 与多个自定义 ShaderMaterial，但它们共享同一套 uniforms 对象（uTime / uClickPos / uFocusPos / uRippleGain / uEffectGain …），因此扫光、涟漪、聚焦波在四层之间天然同步，无需事件广播。

关键算法细节（工程质量较高）

坐标映射

  • geoUv()：经纬度经 Web Mercator 投影到 DEM 归一化 UV，而非线性插值——与数据源投影一致。
  • terrainHeightAt()：按 PlaneGeometry 的 (a,b,d)/(b,c,d) 三角对角线插值，而非双线性，保证射线采样与渲染网格完全贴合。
  • maskAt()：把省界遮罩画到 canvas 取像素，用于裁掉矩形 DEM 的空角。

点云 / 连线生成

  • 固定随机种子 0x1a72c4 + LCG → 确定性拓扑，刷新不产生新噪声。
  • 六方晶格布点（spacing 0.058 m），mask 裁剪后实测 5,635 个点、约 1.1 万条连线。
  • 连线只连"近且高差小"的邻点，并沿真实 DEM 三角面每 ~4 mm 重采样，统一抬高 3.5 mm 防深度冲突——无跨谷弦、无悬空中点。
  • radiusFrom()：按省域内最远点线样本自动计算选中地点的涟漪传播半径。

七、部署与"10 天到期"机制

线上测试地址当前仍可访问： https://hunan-terrain-ar-preview.yytsky1.workers.dev/ 返回 200。 截止时间硬编码在 wrangler.json 的 PREVIEW_EXPIRES_AT = 2026-10-08T10:52:23Z（北京时间 10-08 18:52）。
  • assets.run_worker_first: true：所有请求先过 Worker，用服务器时间判断到期，改访客本机时钟无法绕过。
  • 到期后首页与所有素材直链统一返回 HTTP 410；到期前也用 Cache-Control: no-store 防浏览器持久缓存。
  • 安全头：X-Robots-Tag: noindex、Permissions-Policy: camera=(self), microphone=(), geolocation=()、nosniff。
  • Worker 测试覆盖：到期前放行 + 到期拦截首页/脚本/素材直链 + 非法截止时间 fail-closed。
  • 机制边界（文档已诚实说明）：到期不删除私密仓库与 Cloudflare 配置；已载入内存的画面或他人已保存的副本不受远程撤回控制。

八、工程亮点

  • 诚实的技术边界标注：AR 免责红字常驻界面，AR-INTEGRATION.md 给出接入清单（统一世界锚点、One Euro + slerp 滤波、短时丢失冻结/持续丢失淡出、按真实设备重标阈值）。这在演示类项目里很少见。
  • 确定性可复现：固定随机种子，刷新与重载不产生新噪声；DEM→资产转换脚本可重跑。
  • 几何严谨：连线沿真实 DEM 三角面重采样、按 PlaneGeometry 对角线插值，视觉与物理一致。
  • 零构建依赖：Three.js 本地 vendor + importmap，可完全离线运行。
  • 发布隔离：白名单构建，研究资料与原始数据不进公开产物。
  • 隐私友好：摄像头仅本地合成，不请求麦克风、不录制、不上传。

十、总体评价与建议

结论：这是一个完成度与工程自律都明显高于一般"演示 Demo"的前端项目。它在纯浏览器环境里用真实 DEM 做出了贴近 HoloLens 空间扫描语言的视觉，且对"这是模拟、不是真 AR"保持了罕见的诚实标注；代码里对投影、三角插值、深度冲突、防抖阈值等细节处理得很扎实。

当前最大障碍不是技术，而是可访问性：仓库已不可公开拉取，需要先解决访问权限，否则协作与交接无法进行。

建议优先级：

  1. P0 — 确认并恢复仓库访问权限（公开或提供凭据）。
  2. P1 — 建立真实 AR 跟踪验证路线（文档已给清单：统一锚点 + 自适应滤波 + 丢失策略 + 现场验收用例），这是从"演示"到"展项"的关键一步。
  3. P1 — 地点文案科学审校 + 概念影像替换为授权实景素材。
  4. P2 — 图集转 WebP/AVIF 并懒加载，压缩首屏体积。
  5. P2 — 为 geoUv / terrainHeightAt / 点云拓扑补单元测试（可用 Node 直接跑纯函数部分）。
  6. P3 — 补充 LICENSE，明确复用边界。
